# romm

A [RomM](https://github.com/rommapp/romm) server's library on the card (tested against RomM 5.4.1). With the `url` setting set (off until then: without a server it adds nothing), a RomM folder on the root has a folder for each of the server's platforms with roms that the launcher has a system for, listing their roms. A rom not on the card yet launches by downloading first, into `Roms/<system>/` (the card's folder whose name ends in the system's tag, or the name stock gives it), on a download screen with a progress bar and **B** to cancel, and in the status pill; it's written to a hidden temporary file in that folder, checked against the size the server gave, and renamed into place, then the game launches. Roms of more than one file, which RomM serves as a zip, aren't listed. Platforms map to systems by RomM's slug: `gb` GB, `gbc` GBC, `gba` GBA, `nes` and `famicom` FC, `fds` FDS, `snes` and `sfam` SFC, `genesis` MD, `sms` SMS, `gamegear` GG, `sg1000` SG1000, `segacd` SEGACD, `sega32` 32X, `psx` PS, `tg16` PCE, `neo-geo-pocket` NGP, `neo-geo-pocket-color` NGPC, `virtualboy` VB, `pokemon-mini` PKM, `lynx` LYNX, `atari2600` A2600, `atari5200` A5200, `atari7800` A7800, `colecovision` COLECO, `c64` C64, `c128` C128, `vic-20` VIC, `cpet` PET, `c-plus-4` PLUS4, `acpc` CPC, `amiga` PUAE, `msx` and `msx2` MSX, `pico` P8, `arcade` FBN and `doom` PRBOOM; other platforms are left out. The lists are kept in `.userdata/<platform>/launcher/romm/`, so the folders open at once, and fetched again in the background when a folder opens and its list is more than a minute old. When a game from RomM comes back, its save in `Saves/<tag>/` (whichever of minarch's save names is newest) is uploaded if its MD5 differs from the last one synced (the `sync` setting, on by default), into a slot of its own on the server that keeps the last `keep` uploads (10 by default); one that can't go up is tried again the next time the launcher starts. **Y** on a game from RomM (the `button` setting picks another, shared with other plugins' actions there) opens Flashback: the game's saves and save states on the server, newest first, with their times and sizes; **A** restores one after a confirm, first copying the file on the card to `.userdata/<platform>/launcher/romm/backups/<tag>/`, **X** fetches the list again and **B** goes back. A state restores only in minarch's own format (`.st0` to `.st9`) and only where the system has one state folder in `.userdata/shared`. Nothing goes over the network while Wi-Fi is off or not connected; it says so instead. The `user` and `password` settings log in with a RomM user (HTTP Basic), or with `user` empty, `password` holds a RomM API token. `url`, `user`, `password`, `pin` and `ca_file` are protected by the launcher's PIN, and `password` is write-only and never logged. `http://` sends the login in clear text, so use it only on a network you trust. `https://` uses BearSSL (TLS 1.2), checking the server's certificate against the device's CA certificates (NextUI's bundle on h700, else the system's at `/etc/ssl/certs/ca-certificates.crt` and the usual places) or the `ca_file` setting's, which needs the server's name, not an address; for a self-signed home server, set `pin` to its certificate's SHA-256 fingerprint (`openssl x509 -noout -fingerprint -sha256 -in cert.pem`), which is then the only certificate trusted. Without either, `https://` is refused rather than left unchecked. Certificates are checked against the device's clock. Requests time out after 8 seconds connecting and 20 seconds without data, redirects are followed only on the same server (up to 3), and downloads, lists and saves are capped in size. From LodorOS.
