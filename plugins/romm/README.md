# romm

A [RomM](https://github.com/rommapp/romm) server's library on the card (tested against RomM 5.4.1). With the `url` setting set (off until then: without a server it adds nothing), a RomM folder on the root has a folder for each of the server's platforms with roms that the launcher has a system for, listing their roms. A rom not on the card yet launches by downloading first, into `Roms/<system>/` (the card's folder whose name ends in the system's tag, or the name stock gives it), on a download screen with a progress bar and **B** to cancel, and in the status pill; it's written to a hidden temporary file in that folder, checked against the size the server gave, and renamed into place, then the game launches. A rom of more than one file, which RomM serves as a zip, is unpacked into `Roms/<system>/<game>/`, with a `<game>.m3u` listing its discs (the `.cue` files when it has them, as RomM picks them) in place of RomM's own when it has two or more, so NextUI shows the folder as one game; it's listed at its `.m3u` (or its one disc) and launches there, and its saves and states go by that name as minarch's do. A zip of one file lands as that file. The zip goes to a hidden temporary file, then every entry is checked before anything is written: a zip with an absolute path, `..`, a backslash, a NUL or other character the card can't hold, two names that differ only in case, a link or anything but a plain file or folder, an encrypted entry, or sizes that don't add up (over 2048 entries, a file over 4 GB, 16 GB in all, more than the size RomM gave plus 64 KB, or an entry claiming to inflate past 1032 to 1) is refused whole. Its files are written to temporary names in a hidden folder, never through a link, and the folder is moved into place only once every file is in; a cancel or error removes only what it made, and a folder or file of the game's name already on the card is never written over. Platforms map to systems by RomM's slug: `gb` GB, `gbc` GBC, `gba` GBA, `nes` and `famicom` FC, `fds` FDS, `snes` and `sfam` SFC, `genesis` MD, `sms` SMS, `gamegear` GG, `sg1000` SG1000, `segacd` SEGACD, `sega32` 32X, `psx` PS, `tg16` PCE, `neo-geo-pocket` NGP, `neo-geo-pocket-color` NGPC, `virtualboy` VB, `pokemon-mini` PKM, `lynx` LYNX, `atari2600` A2600, `atari5200` A5200, `atari7800` A7800, `colecovision` COLECO, `c64` C64, `c128` C128, `vic-20` VIC, `cpet` PET, `c-plus-4` PLUS4, `acpc` CPC, `amiga` PUAE, `msx` and `msx2` MSX, `pico` P8, `arcade` FBN and `doom` PRBOOM; other platforms are left out. The lists are kept in `.userdata/<platform>/launcher/romm/`, so the folders open at once, and fetched again in the background when a folder opens and its list is more than a minute old. When a game from RomM comes back, its save in `Saves/<tag>/` (whichever of minarch's save names is newest) is uploaded if its MD5 differs from the last one synced (the `sync` setting, on by default), into a slot of its own on the server that keeps the last `keep` uploads (10 by default); one that can't go up is tried again the next time the launcher starts. **Y** on a game from RomM (the `button` setting picks another, shared with other plugins' actions there) opens Flashback: the game's saves and save states on the server, newest first, with their times and sizes; **A** restores one after a confirm, first copying the file on the card to `.userdata/<platform>/launcher/romm/backups/<tag>/`, **X** fetches the list again and **B** goes back. A state in any of the layouts minarch writes (its own `.st0` to `.st9`, or RetroArch's `.state`, `.state1` to `.state9`, `.state.0` to `.state.9` and `.state.auto`) restores under the name the State format setting gives it, into `.userdata/shared/<tag>-<core>/` for the core the system's emulator pak runs, else the only state folder the system has, else the one named for the emulator the server recorded; a state in another layout, or with no way to tell its folder, can't be restored. A game launched from its folder in `Roms` has Flashback there too. Another plugin can open a game's Flashback with `run_action("romm.flashback", <the game's full path>)`. Nothing goes over the network while Wi-Fi is off or not connected; it says so instead. The `user` and `password` settings log in with a RomM user (HTTP Basic), or with `user` empty, `password` holds a RomM API token. `url`, `user`, `password`, `pin` and `ca_file` are protected by the launcher's PIN, and `password` is write-only and never logged. `http://` sends the login in clear text, so use it only on a network you trust. `https://` uses BearSSL (TLS 1.2), checking the server's certificate against the device's CA certificates (NextUI's bundle on h700, else the system's at `/etc/ssl/certs/ca-certificates.crt` and the usual places) or the `ca_file` setting's, which needs the server's name, not an address; for a self-signed home server, set `pin` to its certificate's SHA-256 fingerprint (`openssl x509 -noout -fingerprint -sha256 -in cert.pem`), which is then the only certificate trusted. Without either, `https://` is refused rather than left unchecked. Certificates are checked against the device's clock. Requests time out after 8 seconds connecting and 20 seconds without data, redirects are followed only on the same server (up to 3), and downloads, lists and saves are capped in size. From LodorOS.
