# battery-logger

Logs how much battery each game used to `.userdata/<platform>/launcher/battery-logger.csv`, one row per session with the columns `date,game,path,seconds,start_percent,end_percent,drain_percent,percent_per_hour,charged`. The launcher exits while a game runs, so it reads the battery level and charging state in `pre_launch`, just before the game starts, keeps that reading in `/tmp`, and reads them again in `post_return`, as the launcher starts after the game. `seconds` is the time between the two readings by `CLOCK_MONOTONIC`, which leaves out time the device was suspended; `date` is the local time at launch and `path` is relative to the card. Paks aren't logged, and a session that ends in a reboot or power cut is dropped, since `/tmp` is cleared and `post_return` doesn't run. No row is written when either reading isn't a level from 1 to 100, for sessions shorter than the `min_minutes` setting (1 by default), or for sessions that charged (charging at either reading, or the level went up), unless the `charged` setting is on, which logs them with `charged` set to `yes` and the drain columns empty. Fields with commas, quotes or spaces at either end are quoted, with quotes doubled, and newlines become spaces. Each row goes in with one synced write, and a last row a power cut left unfinished is cut off before the next is added. When the file would grow past the `max_kb` setting (256 by default), it's renamed to `battery-logger.old.csv`, replacing the last one, and a new file is started. On a platform without a battery, such as desktop, it loads but logs that it's unsupported and does nothing, and its name on the Plugins page says so. Other plugins read the last 64 sessions it logged, on any platform, with its `battery.history` service, as each session's start, length and battery levels (see PLUGINS.md). From marcelopcx and kUI.
