# tags

Your own tags on games, as folders. **Y** on a game (the `button` setting picks another), alongside other plugins' actions there, opens a checklist of every tag for it, with how many games on the card have each: **A** ticks or clears a tag, **A** on New tag names a new one on the keyboard and puts it on the game (a name another tag has, ignoring case, picks that tag), **X** deletes a tag no game on the card has, after a confirm, and **B** goes back. The action is `tags.edit`, so an FN button or `button-remap` can open it too. A game is tagged as stock records it in recents: a game folder or a disc of a multi-disc game as its `.m3u` (or a cue-sheet folder as its `.cue`), and a pak or rom as itself. A Tags folder on the root (the `root` setting, on by default), shown while a tag has a game on the card, has a folder per tag with a game on the card, each listing those games. One folder on the root, rather than a row per tag, keeps the root's consoles together however many tags there are. Each tag with a game on the card also gets a tile in the quick menu's top row that opens its folder (the `tiles` setting, on by default), for up to 8 tags by name; tiles are made as the launcher starts, so a new tag gets its tile the next time it starts, such as after a game. The tags are in `.userdata/<platform>/launcher/tags.txt`: a tag's name on a line of its own, then a line for each of its games with the name, a tab and the game's card-relative path. It's written to a temporary file that replaces it, so a power cut leaves the old file or the new one, and read again whenever it changes. Games no longer on the card stay in the file in case the card comes back. Names are trimmed, up to 63 bytes, and can't have a slash or start with a dot or `#`. Other plugins read each tag as the entry set `tags:<name>`, with the name exactly as the tag has it. From radther.
