# platform-jump

**L1** and **R1** jump between systems instead of letters. Inside a system, or any folder in it, they open the previous or next system in the root's order, as if you'd backed out and opened it there, so **B** goes back to the root with that system selected. In Recently Played, collections, Favorites and other lists with games from several systems (the `lists` setting, on by default), they move to the first game of the previous or next system, taking systems in the order they first appear in the list. On the root they jump letters, unless the `root` setting (off by default) has them move between the system rows, past Recently Played, Collections, Tools and other plugins' rows. Past the last system they wrap around to the first (the `wrap` setting, on by default). Everywhere else, and where there's only one system to go to, they jump letters as stock does. Both kinds of jump repeat while the shoulder is held, at stock's pace, so holding R1 inside a system steps through the systems; on a launcher without `override_repeat` they go once per press. It takes L1 and R1 with `override_button`, so other plugins' `bind_button` bindings on them don't run and the shared-button menu never opens on them; if another plugin earlier in load order already overrides either one, platform jump doesn't load. With a root another plugin replaced, such as `all-games`', the systems come from the next list of systems shown, such as its Systems folder, and **B** from a system it opened goes back through the Roms folder. From kUI.
