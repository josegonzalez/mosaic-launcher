# emulator-override

Picks the emulator pak a game launches with. **Y** on a game (the `button` setting picks another), alongside other plugins' actions there, lists Default, the system's own pak, then the other emulator paks on the card known to run its games: GB, GBC, SGB and MGBA for Game Boy and Game Boy Color games, MGBA for Game Boy Advance, and SFC and SUPA for each other. The `all` setting (off by default) lists every emulator pak instead. Picking one saves it for that game, and Default clears it. A game folder, its discs and its `.m3u` share one choice. The choices are in `.userdata/<platform>/launcher/emulator-override.txt`, one card-relative game path, a tab and the pak's name per line. Before each launch the choice is checked again: the pak has to be in `Emus/<platform>/` or `.system/<platform>/paks/Emus/`, found the way stock finds a system's pak, with a `launch.sh` that's a regular file and doesn't lead out of its pak through a link. Otherwise the game launches as usual and the launcher log says why. A valid choice replaces the launch with the pak's `launch.sh` and the game's path, quoted as stock quotes its own, so the game's saves and states go under that pak's name, as when a system folder is renamed to it. Paks launch as usual. With another plugin that replaces launches, only the first of them in load order replaces a launch: when that's the other plugin, the override's `replace_launch` is refused and logged and the other's command runs, and when it's `emulator-override`, the other's is refused. Other plugins ask for a game's choice with its `emulator.choice` service, for a game or game folder's `path`, as the pak's name and its `launch.sh`, which is empty when the pak fails the launch's check (see PLUGINS.md). From LodorOS.
